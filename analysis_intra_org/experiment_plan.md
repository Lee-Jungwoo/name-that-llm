# 실험 계획: 헷갈리는 쌍을 가르는 손실 + 규제

[report.md](report.md)의 분석을 바탕으로 짠 계획입니다. 아직 아무것도 돌리지 않았습니다.

## 한 줄 요약

LoRA Stage 2의 손실에 **헷갈리는 쌍의 점수 차를 벌리는 항**을 더합니다. 이 항은 **v4 예측에서 너무 멀어지지 않게 하는 KL 규제**와 함께 씁니다. 짝 손실은 같은 프롬프트에 대한 두 답으로 만들어 주제 지름길을 막습니다. GPU를 쓰기 전에, 쌍별 bias만 다시 맞추는 무료 기준선부터 잽니다.

## 손실 설계

현재 Stage 2 손실은 `F.cross_entropy(logits, y, label_smoothing=0.05)`입니다(`name_that_llm_v4.ipynb`의 `train_stage`). 여기에 두 항을 더합니다.

$$
L = \underbrace{\text{CE}_{ls=0.05}}_{\text{지금}} + \lambda \cdot L_{\text{pair}} + \beta \cdot \text{KL}(p_{\text{ref}} \,\|\, p)
$$

### 쌍 손실 A: 지문 하나 단위 마진

정답이 $i$인 지문에서, $i$와 헷갈리는 상대 $j \in C(i)$에 대해 로짓 차 $z_i - z_j$가 마진 $m$보다 작으면 벌점을 줍니다.

$$
L_A = \frac{1}{|C(i)|} \sum_{j \in C(i)} \text{softplus}\big(m - (z_i - z_j)\big)
$$

- CE는 18개 전체에 확률을 나누지만, 이 항은 헷갈리는 상대와의 차이에만 작용합니다.
- $C(i)$가 비어 있는 지문(대상 쌍이 없는 모델)은 0입니다.

### 쌍 손실 B: 같은 프롬프트 짝 순위

같은 프롬프트에 대한 $i$의 답 $x_i$와 $j$의 답 $x_j$를 같은 배치에 넣습니다. "$i$다운 정도" $z_i - z_j$가 $x_i$에서 $x_j$보다 $m$ 이상 크도록 합니다.

$$
s = (z_i - z_j)(x_i) - (z_i - z_j)(x_j), \qquad L_B = \text{softplus}(m - s)
$$

- 분류 헤드가 선형이라 $s = (w_i - w_j) \cdot (h(x_i) - h(x_j))$입니다. bias와, 두 답이 공유하는 주제 성분이 빠집니다.
- 분석에서 같은 프롬프트로 짝지으면 쌍 구분이 쉬워졌습니다(sol·terra 0.826 → 0.887). 이 방향을 학습 신호로 직접 씁니다.
- train은 프롬프트마다 18개 모델 답이 다 있어서 짝을 바로 만들 수 있습니다. fold마다 학습 프롬프트 약 120개 × 쌍 14개 = 짝 약 1,700개입니다.

### 규제

| 규제 | 내용 | 막으려는 것 |
|---|---|---|
| R1. 기준 모델 KL | $\beta \cdot \text{KL}(p_{\text{ref}} \,\|\, p)$. $p_{\text{ref}}$는 같은 fold의 v4 Stage 2 모델 로짓입니다. 학습 전에 한 번 계산해 두면 추가 순전파가 없습니다. | 쌍 손실 때문에 잘 맞히던 모델(opus-4-6, gemini-3.1-pro 등)의 예측이 흔들리는 것 |
| R2. 마진 상한과 워밍업 | softplus는 차이가 $m$을 넘으면 0에 가까워져 끝없이 벌리지 않습니다. $\lambda$는 처음 20% 스텝 동안 0에서 목표값으로 올립니다. | 과신, 학습 초반에 쌍 손실이 표현을 흔드는 것 |
| R3. 짝 데이터 제한 | 쌍 손실 B는 train의 같은 프롬프트 짝으로만 만듭니다. 풀 지문은 쓰지 않습니다. | 풀의 모델별 주제 쏠림을 지름길로 배우는 것 |

- 기존의 weight decay 0.01, label smoothing 0.05, gradient clip 1.0은 그대로 둡니다.
- 온도는 학습 후 OOF로 다시 맞춥니다. 쌍 손실이 로짓 크기를 바꾸기 때문입니다.

### 구현 스케치

```python
PAIR = torch.zeros(K, K, dtype=torch.bool)    # 대칭 쌍 집합 C_all 또는 C_mid
for a, b in PAIRS:
    PAIR[L2I[a], L2I[b]] = PAIR[L2I[b], L2I[a]] = True

def pair_margin_loss(logits, y, margin=1.0):          # 쌍 손실 A
    gap = logits.gather(1, y[:, None]) - logits       # (B, K): z_y - z_j
    m = PAIR.to(logits.device)[y].float()             # 정답 y와 헷갈리는 상대
    per = (F.softplus(margin - gap) * m).sum(1) / m.sum(1).clamp(min=1)
    return per.mean()

def paired_rank_loss(z_a, z_b, i, j, margin=1.0):    # 쌍 손실 B. z_a: i 답의 로짓, z_b: 같은 프롬프트 j 답의 로짓
    s = (z_a[:, i] - z_a[:, j]) - (z_b[:, i] - z_b[:, j])
    return F.softplus(margin - s).mean()

def kl_to_ref(logits, ref_logits):                    # 규제 R1
    return F.kl_div(F.log_softmax(logits, 1), F.log_softmax(ref_logits, 1),
                    log_target=True, reduction="batchmean")
```

- 쌍 손실 B는 배치 구성을 바꿔야 합니다. 지금 마이크로 배치는 4개(echo라서)입니다. 절반의 스텝은 지금처럼 무작위 배치로, 나머지 절반은 "프롬프트 2개 × (i 답, j 답)" 배치로 돌립니다. 짝 배치에도 CE와 KL은 그대로 겁니다.
- $p_{\text{ref}}$는 Kaggle 데이터셋 `ntl-lora-weights-v4-echo-cv`의 `ntl_lora_fold{k}.pt`로 fold k의 학습 지문 로짓을 미리 뽑아 둡니다.

## 실험 단계

### 0단계: GPU 없이 하는 기준선 (쌍별 bias)

`oof_v4.npz`만 씁니다. 블렌드 log 확률에서 top-2가 쌍 $(i, j) \in C$일 때 $z_i$에 bias $b_{ij}$를 더합니다. bias는 fold 4개로 맞추고 남은 fold에서 평가합니다(nested).

- 경계 근처 오답이 많으니 bias만으로도 일부가 뒤집힐 수 있습니다. 이 단계의 이득이 1단계 이후와 비슷하면 표현 학습이 아니라 문턱 조정 효과입니다. 그러면 GPU 실험은 줄입니다.
- 기존 Sinkhorn(클래스 비율 보정)과 겹치는 효과인지도 같이 봅니다.

### 1단계: LoRA Stage 2 실험

모두 저장된 Stage 1 가중치(`ntl_lora_stage1.pt`)에서 Stage 2만 다시 학습합니다. 설정은 v4와 같습니다(2 epochs, lr 5e-5, 실효 배치 8, echo).

| 실험 | 손실 | 쌍 | 규제 | 목적 |
|---|---|:-:|:-:|---|
| E0 | CE | - | - | 기준. **시드 2개**로 돌려 시드 잡음을 잽니다. |
| E1 | CE + λ·A | `C_all` | 없음 | 쌍 손실만의 효과와 부작용 |
| E2 | CE + λ·A + β·KL | `C_all` | R1, R2 | 규제의 효과(E1과 비교) |
| E3 | CE + λ·B + β·KL | `C_all` | R1, R2, R3 | 같은 프롬프트 짝의 효과(E2와 비교) |
| E4 | E2, E3 중 나은 쪽 | `C_mid` | 같음 | 어려운 4쌍을 빼면 나아지는지 |

- 하이퍼파라미터 후보: $\lambda \in \{0.1, 0.3, 1.0\}$, $m = 1.0$(오답 점수 차 중앙값 0.65\~0.85), $\beta \in \{0.5, 1.0\}$.
- **선별**: fold 0, 1(지문 1,080개)로 E1\~E4와 $\lambda$, $\beta$ 조합 약 10개를 봅니다. fold 0 하나(540개)는 모델당 30개라 너무 흔들립니다.
- **확정**: 상위 2개 설정만 5-fold 전체로 돌립니다.
- 시간(L4, fold당 약 7분 + 짝 배치 10% 안팎): 선별 약 10개 × 2 fold ≈ 2.5시간, 확정 2개 × 5 fold ≈ 1.2시간, 제출용 전체 학습 1회 약 9분입니다.

### 2단계: 블렌드와 제출

- n-gram OOF(`ng_oof_lp`)는 그대로 두고 LoRA OOF만 바꿔 블렌드(w = 0.6)를 다시 계산합니다. LoRA 온도는 OOF로 다시 고릅니다.
- 확정 기준을 넘으면 train 전체로 Stage 2를 한 번 더 학습해 제출합니다(v4 full 방식).

## 예상과 판단 기준

- **예상**: 이득은 GPT 5.6 세 모델과 gemini-3.6·3.7에서 나올 것입니다. GLM 쌍과 3.7·3.8은 오답이 쌍 안에서 자리만 바꿀 가능성이 큽니다. E4(`C_mid`)가 E2/E3과 같거나 나으면 이 예상이 맞는 것입니다.
- **E1 > E2**인데 나머지 모델 recall이 떨어졌다면 KL 규제가 제 역할을 한 것입니다. BA로는 E2를 고릅니다.
- **E3 > E2**이면 같은 프롬프트 짝이 효과가 있다는 뜻입니다. 테스트에서도 프롬프트 묶음을 쓰는 후처리(현재 프롬프트 중심화)와 이어서 볼 만합니다.
- **0단계 bias가 E2/E3과 비슷하면** 손실을 바꾼 효과가 아니라 문턱 효과입니다. 그러면 0단계만 채택합니다.

## 범위 밖 (이번에는 하지 않음)

- n-gram 분기는 LinearSVC라 이 손실을 바로 붙일 수 없습니다. 쌍별 이진 SVM을 2단으로 붙이는 방법이 있지만, 분석에서 풀로 학습한 전용 분류기가 v4보다 낮았으므로 미룹니다.
- 어려운 4쌍은 다른 정보원(예: 토큰 확률 기반 피처, 더 큰 기반 모델)이 필요해 보입니다(추정).
