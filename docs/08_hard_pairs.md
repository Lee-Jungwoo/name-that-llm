# 8. 아직 헷갈리는 모델 쌍: 두 모델의 지문은 무엇이 다른가

[← 전체 문서](README.md)

v9가 바꾸는 것은 LoRA 분기뿐이므로, 그 밖의 부분이 같은 v8 OOF로 가장 많이 헷갈리는 8쌍을 골랐습니다. 쌍마다 두 모델의 지문이 무엇이 다른지 사람이 읽을 수 있는 단위(문체 피처, 단어·구두점 표지)로 정리하고, v8이 틀린 지문이 왜 틀렸는지 같은 단위로 설명했습니다. 결론은 세 가지입니다.

1. **가장 헷갈리는 네 쌍은 설명할 수 있는 차이가 거의 없습니다.** gemini-3.7-flash · 3.8-flash, glm-5.3 · glm-5.3-flash, claude-fable-5 · GLM 두 모델이 여기에 듭니다. 같은 프롬프트로 짝지어도 효과 크기 |dz|가 0.2 이상인 문체 피처가 거의 없습니다. 차이가 가장 큰 표지도 지문의 몇 %에만 나옵니다. 표지 87개로 만든 설명 가능한 분류기의 AUC는 0.52~0.60이라 거의 찍는 수준입니다.
2. **이 네 쌍에서 v8이 틀린 지문은 길이로 많이 설명됩니다.** v8은 glm-5.3 지문이 짧으면 맞히고(평균 98.5단어) 길면 flash나 fable-5로 보냅니다(148단어, 135단어). gemini-3.7-flash는 길면 맞히고(142.8단어) 짧으면 3.8-flash로 보냅니다(98.3단어). 그런데 같은 프롬프트로 짝지으면 두 모델의 길이 차이는 작습니다. v8은 실제로는 약한 길이 신호에 기대고 있고, 길이가 반대로 나온 지문에서 틀립니다(추정).
3. **나머지 네 쌍은 경향은 뚜렷하지만 지문마다 겹칩니다.** kimi-k3는 em dash를 쓰고(train 지문의 52%, gpt-5.5는 13%) gpt-5.6-terra는 `rather than`과 `small`을 씁니다. v8이 틀린 지문은 대개 **자기 모델의 표지가 빠졌거나 상대 모델의 표지가 들어간 지문**입니다. 예를 들어 gpt-5.5로 틀린 kimi-k3 지문에는 em dash가 9%에만 있습니다(맞힌 kimi-k3 지문은 56%).

> [!NOTE]
> **기준**
> - v9는 아직 학습 전이라 OOF가 없습니다. 이 문서의 예측은 **v8 제출 커널의 OOF**([analysis_v8/oof_v8.npz](../analysis_v8/oof_v8.npz))로 만든 게이트 뒤 argmax입니다(블렌드 LoRA 0.6 / DeBERTa 0.2 / n-gram 0.2, 회사 게이트, Sinkhorn 전). 로컬에서 낸 OOF BA는 블렌드 0.5982, 게이트 뒤 0.6023으로 커널 로그와 같습니다.
> - v9는 LoRA를 다시 학습하므로 쌍의 순위와 오답 수는 바뀔 수 있습니다. 반면 2장의 "두 모델의 지문이 어떻게 다른가"는 데이터에 대한 내용이라 모델과 상관없이 그대로입니다. v9 OOF가 나오면 같은 스크립트에 경로만 바꿔 다시 냅니다(5장).
> - train은 모델당 지문 150개(`claude-fable-5`만 149개)입니다. 지문 하나가 recall 0.0067입니다.
> - Open Pool은 11/25 판 238,750개에서 `flag_kb_proxy_after_ruling` 행, `prompt_canon`이 빈 행, 중복 지문을 뺀 211,219개를 썼습니다.

## 0. 용어

| 용어 | 뜻 |
|---|---|
| 상호 오답 | 쌍 (A, B)에서 A 지문을 B로 예측한 수 + B 지문을 A로 예측한 수. 쌍을 고른 기준입니다. |
| 같은 프롬프트 짝 | 같은 프롬프트에 A와 B가 각각 쓴 지문 두 개. 주제와 요구 길이가 같아서, 두 지문의 차이는 모델 차이만 남습니다. train은 `prompt_id`로 150짝, 풀은 `prompt_canon`으로 1,203~8,348짝입니다. |
| dz | 짝 효과 크기 = 평균(A − B) / 표준편차(A − B). 짝마다 A 값에서 B 값을 뺀 차이로 계산합니다. 0.2면 작음, 0.5면 중간입니다. 양수면 A가 큽니다. |
| DF | 그 표지가 한 번이라도 나온 지문의 비율. "DF 0.52"는 지문 100개 중 52개에 나온다는 뜻입니다. |
| 짝 z | 표지 순위를 매긴 값 = (b − c) / √(b + c). b는 A 지문에만 나온 짝 수, c는 B 지문에만 나온 짝 수입니다(McNemar 검정과 같은 꼴). |
| v8 쌍 AUC | A, B 지문 약 300개를 v8 점수 차이 log p(A) − log p(B)로 줄 세웠을 때, 무작위로 뽑은 A 지문이 B 지문보다 위에 올 확률. 0.5가 찍기, 1.0이 완벽입니다. |
| 설명 가능한 분류기 | 풀 짝 지문으로 학습한 로지스틱 회귀(C = 0.1)입니다. 입력은 표지 60개(쪽마다 짝 z 상위 30개, 있으면 1·없으면 0)와 문체 피처 27개(`log1p` 뒤 표준화), 모두 87개입니다. train A·B 지문으로 AUC를 잽니다. v8과 달리 계수 하나하나가 "이 표지가 있으면 A 쪽"으로 읽힙니다. |
| Spearman ρ | 설명 가능한 분류기 점수와 v8 쌍 점수의 순위 상관. 1이면 두 점수가 지문을 같은 순서로 줄 세운다는 뜻입니다. |

- 아래 네 쌍은 ρ가 0.40~0.59로, v8 판단의 상당 부분이 이 표지들과 같은 방향입니다.
- claude-fable-5와 GLM 두 모델은 셋이 한 묶음입니다. fable-5 지문 149개 중 43개만 맞고 GLM으로 47개가 갑니다(glm-5.3-flash 27, glm-5.3 20). glm-5.3 150개 중에서는 36개가 맞고 flash로 35개, fable-5로 29개가 갑니다.

## 2. 쌍별 차이

표의 숫자는 train(짝 150개)과 풀(짝 수는 각 절 첫 줄)의 값입니다. **방향이 train과 풀에서 같은 것만** 적었습니다. 풀에서만 보이는 표지는 3.2절에 따로 모았습니다.

### 2.1 gemini-3.7-flash · gemini-3.8-flash (상호 오답 82, 1위)

풀 짝 3,063개. v8 쌍 AUC 0.698, 같은 프롬프트 짝에서 3.7 지문 쪽 점수가 더 높은 비율 0.767.

| 차이 | 3.7-flash | 3.8-flash | 크기 |
|---|:-:|:-:|---|
| 평균 문장 길이(단어) | train 23.9 / 풀 22.6 | 22.8 / 21.7 | dz +0.17 / +0.19 |
| 단어 수 평균 | train 117 / 풀 109 | 101 / 106 | dz +0.21 / **+0.05**. 3.7이 더 긴 짝은 train에서 60% |
| 하이픈 복합어(`self-similar` 같은 글자-글자) DF | train 0.18 / 풀 0.51 | 0.10 / 0.45 | |
| `profound` DF | train 0.18 / 풀 0.078 | 0.093 / 0.060 | |
| `of the` DF | train 0.33 / 풀 0.27 | 0.21 / 0.24 | |
| 곱은 큰따옴표 `“` DF | train 0 / 풀 0.001 | 0.020 / 0.014 | 3.8만 씀. 나와도 지문의 2% |

- **문체 피처 27개 중 |dz| ≥ 0.2인 것이 없습니다**(가장 큰 것이 문장 길이 +0.19). 설명 가능한 분류기 AUC는 0.586입니다.
- **v8이 틀린 지문은 길이와 하이픈으로 갈립니다.**

| | 지문 | 단어 수 | 문장 길이 | 하이픈 복합어 DF |
|---|:-:|:-:|:-:|:-:|
| 3.7-flash 맞힘 | 63 | 142.8 | 25.1 | 0.32 |
| 3.7-flash → 3.8-flash로 틀림 | 49 | **98.3** | 21.9 | **0.06** |
| 3.8-flash 맞힘 | 91 | 92.7 | 21.2 | 0.02 |
| 3.8-flash → 3.7-flash로 틀림 | 33 | **130.0** | 24.7 | **0.33** |

- v8 쌍 점수와 단어 수의 Spearman ρ는 +0.35, 하이픈 복합어와는 +0.39입니다. v8은 대략 "길고 하이픈 복합어가 있으면 3.7"로 판단하고, 짧은 3.7 지문과 긴 3.8 지문에서 틀립니다.
- 그런데 **풀에서는 같은 프롬프트의 두 지문 길이가 거의 같습니다**(dz +0.05). train의 길이 차이(dz +0.21)가 두 모델의 일반적인 성질인지, train을 만들 때의 사정인지는 이 데이터로 가를 수 없습니다(추정).
- 예(prompt p091, v8이 3.7 지문을 3.8로 예측): 3.7 지문은 두 문장 41단어이고, 같은 프롬프트의 3.8 지문은 87단어입니다. 이 프롬프트에서는 3.7이 더 짧게 써서 "길면 3.7"이라는 신호가 반대로 작동했습니다.

### 2.2 glm-5.3 · glm-5.3-flash (상호 오답 56)

풀 짝 8,134개. v8 쌍 AUC 0.663, 짝 정확도 0.693.

| 차이 | glm-5.3 | glm-5.3-flash | 비고 |
|---|:-:|:-:|---|
| `even` DF | train 0.107 / 풀 0.106 | 0.167 / 0.132 | flash 쪽에만 나온 짝 16, glm-5.3 쪽 7 |
| 첫 단어 `Deep` DF | train 0.027 / 풀 0.008 | 0.060 / 0.016 | |
| `finally` DF | train 0.027 / 풀 0.035 | 0.053 / 0.048 | |
| en dash `–` DF | train 0 / 풀 0.002 | 0.007 / 0.011 | |

- **문체 피처 27개 중 풀에서 |dz|가 0.07을 넘는 것이 없습니다.** train에서만 보이는 세미콜론 차이(flash가 많음, dz −0.20)는 풀에서 방향이 반대입니다(+0.04).
- 위 표지들은 지문의 17% 이하에만 나오고, 두 모델의 차이는 1~6%p입니다. 많이 나오는 표지 중 차이가 가장 큰 `like`도 풀 DF 0.41 vs 0.44로 3%p 차이입니다. 설명 가능한 분류기 AUC는 0.602입니다.
- **v8이 틀린 지문은 길이로 갈립니다.**

| | 지문 | 단어 수 | 하이픈 복합어 DF |
|---|:-:|:-:|:-:|
| glm-5.3 맞힘 | 36 | **98.5** | 0.22 |
| glm-5.3 → flash로 틀림 | 35 | **148.2** | 0.51 |
| flash 맞힘 | 60 | **142.0** | 0.45 |
| flash → glm-5.3으로 틀림 | 21 | **94.0** | 0.29 |

- v8 쌍 점수와 단어 수의 Spearman ρ는 −0.32입니다(길수록 flash 쪽). 하지만 **같은 프롬프트 짝의 길이 차이는 train dz −0.10, 풀 dz −0.03으로 작습니다.** v8은 두 모델 사이에 실제로는 거의 없는 길이 신호에 기대고 있습니다(추정). 하이픈 복합어도 긴 지문에 많이 나오므로 길이와 함께 움직입니다.

### 2.3 claude-fable-5 · glm-5.3-flash / claude-fable-5 · glm-5.3 (상호 오답 51, 49)

- 곱은 따옴표는 셋 다 쓰지 않습니다([analysis_intra_org/report.md](../analysis_intra_org/report.md)).

- fable-5를 glm-5.3-flash로 틀린 지문 27개에는 풀에서 찾은 fable-5 표지 상위 3개(첫 단어 `Imagine`, `imagine`, `imagine a`)가 하나도 없습니다(맞힌 fable-5는 7%, 7%, 2%).

### 2.4 gpt-5.6-luna · gpt-5.6-sol (상호 오답 49)

풀 짝 8,321개. v8 쌍 AUC 0.839, 짝 정확도 0.867.

| 차이 | luna | sol | 비고 |
|---|:-:|:-:|---|
| em dash `—` DF | train 0.367 / 풀 0.303 | 0.273 / 0.201 | |
| 괄호 `(` DF | train 0.047 / 풀 0.067 | 0.013 / 0.029 | luna 쪽에만 나온 짝 5, sol 쪽 0 |
| 9글자 이상 단어 비율 | train 0.15 / 풀 0.14 | 0.13 / 0.13 | dz +0.45 / +0.19 |
| `rather than` DF | train 0.100 / 풀 0.111 | 0.060 / 0.084 | |
| `is a` DF | train 0.100 / 풀 0.128 | 0.060 / 0.102 | |
| `again` DF | train 0.027 / 풀 0.045 | 0.100 / 0.064 | sol 쪽에만 나온 짝 14, luna 쪽 3 |
| `so` DF | train 0.107 / 풀 0.179 | 0.173 / 0.208 | |
| `then` DF | train 0.147 / 풀 0.207 | 0.180 / 0.245 | |

- 읽어 보면 luna는 설명하고 정의하는 문장(`is a`, `rather than`, 괄호 보충)이 많고, sol은 시간 순서를 따라가는 문장(`then`, `again`, `begins`, `until`)이 많습니다. 이 구분은 표지를 보고 붙인 해석입니다.
- v8이 틀린 지문은 단어 길이와 괄호에서 상대 모델 쪽입니다. sol로 틀린 luna 지문의 평균 단어 길이는 5.37글자로 sol 평균(5.39)과 같습니다(맞힌 luna는 5.49). 괄호는 0%입니다(맞힌 luna 6%). 반대로 luna로 틀린 sol 지문은 단어 길이 5.64, em dash DF 0.35, 괄호 0.04로 luna 쪽입니다.
- 다만 v8이 틀린 지문 79개 중 설명 가능한 분류기도 같은 쪽으로 틀린 비율은 0.49입니다. 오답 전체를 이 표지로 설명할 수는 없습니다.

### 2.5 gemini-3.6-flash · gemini-3.7-flash (상호 오답 42)

## 3. 공통으로 보이는 것

### 3.1 짧은 지문일수록 틀린다

18개 모델 전체에서 단어 수 사분위 구간별 정확도(게이트 뒤 argmax가 정답인 비율)입니다.

| 단어 수 | 지문 | 정확도 |
|---|:-:|:-:|
| 37~65 | 690 | 0.490 |
| 66~102 | 668 | 0.584 |
| 103~159 | 670 | 0.637 |
| 160~278 | 671 | 0.702 |

- 짧은 지문에는 표지가 나올 자리가 적어서 정확도가 낮습니다. 2.1·2.2절의 길이 효과는 이것과 다릅니다. 그 두 쌍에서는 긴 지문도 한쪽 모델로 쏠려서 틀립니다(glm-5.3 → flash로 틀린 지문이 평균 148단어).

### 3.2 풀과 train의 표기 차이

풀에서 큰 차이로 나오지만 train에서는 작거나 반대인 표지가 있습니다. 대부분 따옴표와 하이픈 같은 표기 습관입니다.

| 표지 | 풀 DF | train DF |
|---|:-:|:-:|
| kimi-k3의 곧은 아포스트로피 `'` | 0.355 | 0.233 |
| gpt-5.5의 곧은 아포스트로피 `'` | 0.010 | 0.113 |
| gpt-5.5의 곱은 큰따옴표 `“` | 0.231 | 0.093 |
| gemini flash 세 모델의 하이픈 복합어 | 0.39~0.51 | 0.09~0.18 |
| claude-fable-5의 첫 단어 `Imagine` | 0.108 | 0.054 |

- 풀은 여러 사람이 올린 데이터셋을 모은 것이라(`source_dataset`), 출처마다 따옴표·하이픈 정규화가 달랐을 수 있습니다(추정).
- **v9와 관련이 있습니다.** v9는 LoRA Stage 1을 풀 전체로 학습하므로, 풀에만 있는 표기 신호를 더 많이 배울 수 있습니다. Stage 2(train)에서 바로잡히는지는 v9 OOF로 확인해야 합니다(추정).

### 3.3 v8이 쓰는 신호 중 표지로 설명되는 부분

- 설명 가능한 분류기와 v8의 순위 상관 ρ는 0.22~0.59입니다. v8 판단 중 표지와 겹치는 부분은 쌍에 따라 일부에서 절반 정도입니다.
- 위 네 쌍은 v8도 약하고(AUC 0.65~0.70) 표지 분류기는 더 약합니다(0.52~0.60). 이 쌍들은 **사람이 짚을 수 있는 표면 차이가 거의 없는 쌍**입니다. 같은 기업 모델을 v4로 비교했을 때와 같은 결론입니다([analysis_intra_org/report.md](../analysis_intra_org/report.md)).

## 4. v9 다음에 볼 것

아래는 이 분석에서 나온 제안입니다. 아직 실험하지 않았습니다.

- **위 네 쌍은 피처를 더해서 풀기 어렵습니다**(추정). 표지가 지문의 몇 %에만 나오기 때문입니다. 데이터를 늘리는 쪽이 낫고, [외부데이터_수집.md](외부데이터_수집.md)의 A등급 모델(glm-5.3, claude-fable-5, glm-5.3-flash, gemini-3.7-flash)이 이 네 쌍과 같습니다.
- **gemini-3.7 · 3.8과 GLM 쌍에서 v8은 길이에 기대고 있습니다.** v9 OOF에서도 틀린 지문의 평균 단어 수가 맞힌 지문과 크게 다른지 이 스크립트로 다시 봅니다. 길이 의존이 남아 있으면, 같은 프롬프트의 지문 길이 분포가 비슷한 풀 데이터로 그 쌍의 판단을 보정하는 방법을 검토할 수 있습니다.
- **3.2절의 표기 차이**가 v9 LoRA에 들어갔는지 봅니다. v9 OOF에서 gpt-5.5 · kimi-k3 쌍이 나빠졌다면 첫 번째로 의심할 곳입니다.
