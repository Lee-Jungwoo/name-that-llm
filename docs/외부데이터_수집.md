3. 실행 단계

Step 0. 기존 공개 데이터 먼저 확인





"Name That LLM Open Pool: 224k Clean Passages" (v14)에서 glm-5.3, glm-5.3-flash, Claude 5종의 샘플 수와 품질 확인



부족한 클래스만 직접 생성 대상으로 선정

Step 1. 생성 설정 맞추기 (가장 중요)





출력 형식: 독립적인 한 문단, 40~250단어 (길이를 무작위로 지정)



주제: 철학, 물리, 수학, 생물, CS, 창작 산문



프롬프트: train.csv의 150개 프롬프트와 겹치지 않는 새 프롬프트 (테스트는 prompt-disjoint)



후처리: 대회와 동일하게 가벼운 포맷 정리만 (예: 문단 전체 bold 래퍼 제거)



모델별 권장 설정 적용





GLM-5.3-Flash: thinking enabled만 지원, temperature 1, top_p 0.95



kimi-k3: reasoning on (Open Pool v14 정정 사항)



Claude: 기본 설정(adaptive thinking 기본값) 우선, 소량으로 train과 문체 비교

Step 2. 파일럿 (모델당 50~100개)





각 경로에서 소량 생성



train.csv의 같은 모델 샘플과 길이 분포, em-dash 간격, 리스트 스타일, 종결 방식 비교



특히 AIHubMix coding- 경로가 공식 API와 문체 차이가 있는지 확인



차이가 크면 해당 경로는 버리고 공식 API로 전환

Step 3. 본 수집





목표량 예시: GLM 2종 각 1,000~3,000개, Claude 5종 각 1,000개



동일 프롬프트를 GLM과 Claude 모두에 던져서 쌍(pair) 데이터 구성 (토픽 누수 없이 문체만 학습)



로그 저장: prompt, model_id, provider, temperature, top_p, reasoning 설정, 생성 시각, 원본 응답

Step 4. 검증





prompt-grouped CV로 기존 데이터만 vs 기존+신규 비교



GLM vs Claude 쌍별 recall/혼동 행렬 확인



개선 없으면 생성 설정 재점검 (양보다 분포 일치가 우선)

Step 5. 업로드





Kaggle Dataset으로 업로드 (비공개여도 팀 내 사용은 가능, 팀 외 공유 시 공개 필수)



라이선스와 생성 과정을 데이터셋 설명에 기록
